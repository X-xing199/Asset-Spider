## ✨ 功能特点

### 🎯 四大核心扫描模块（严格区分信息收集与漏洞评估）

| 模块 | 模式 | 功能描述 |
|------|------|---------|
| **🌐 子域名扫描** | ℹ️ 信息收集 | 子域名字典爆破 + DNS解析记录 + 连通性测试，**不含漏洞评估** |
| **🔍 中间件指纹** | ⚠️ 推测性评估 | 多维度指纹识别 + 主动探测 + CVE匹配 + **推测性漏洞类型猜测** |
| **🔌 端口扫描** | ℹ️ 信息收集 | 全端口/高危端口扫描 + 200+端口服务映射，**不含漏洞识别** |
| **💥 FUZZ 攻击** | ⚠️ 推测性评估 | 路径爆破 + 13种攻击类型 + AI赋能爆破路径 + **推测性漏洞猜测** |

### 🧠 AI 智能赋能（推测性分析，不含利用方法）

- **推测性漏洞类型分析**：基于扫描结果，遵循CVE/CWE标准分类，提供漏洞类别、影响范围、风险等级
- **JS 逻辑推测性分析**：分析前端JS中的认证机制、API端点、数据流，推测可能存在的漏洞类型
- **AI 赋能爆破路径**：当目标URL无参数/路径时，AI推荐可能存在漏洞的路径并自动FUZZ测试
- **阶段性小结**：每轮扫描完成后生成资产情报整理或推测性分析报告
- ⚠️ 所有AI分析结果均标注「推测性结果」，不包含具体利用方法或验证步骤

### 🎨 可视化输出

- **6 级漏洞颜色分级**：严重(红加粗)/高危(红)/中高危(黄)/中危(蓝)/中低危(青)/低危(紫)
- **推测性结果标注**：功能2/4的漏洞猜测统一标注「[推测性结果]」前缀
- **实时逐行输出**：存活/死亡状态实时打印，不同漏洞类型独立着色
- **免责声明**：每个功能结尾附带合规免责声明

### ⚡ 性能优化

- **Session 连接池**：复用 TCP 连接，减少握手开销
- **字典缓存**：基于文件修改时间的字典缓存机制
- **多线程并发**：可配置线程数，默认 25 线程
- **Windows 编码修复**：自动处理 GBK/UTF-8 编码问题

## 🚀 快速开始

### 环境要求

- **操作系统**：Windows 10/11、Linux、macOS
- **Python**：3.8 及以上（源码运行时需要）
- **依赖库**：`requests`、`openai`、`pyinstaller`（打包时需要）

### 方式一：一键运行（推荐）

无需安装 Python 环境，直接下载 `AssetSpider.exe` 双击运行：

```bash
# 1. 将 config 文件夹放在 AssetSpider.exe 同级目录
# 2. 双击 AssetSpider.exe 即可启动
```

```
AssetSpider/
├── AssetSpider.exe    # 主程序
└── config/            # 配置文件夹
    ├── ai_config.json      # AI 配置（可选）
    ├── fingerprint.json    # 指纹库
    ├── submin.txt          # 子域名字典
    ├── dir_dict.txt        # 目录字典
    └── ...
```

### 方式二：源码运行

```bash
# 1. 克隆仓库
git clone https://github.com/X-xing199/Asset-Spider.git
cd Asset-Spider

# 2. 安装依赖
pip install requests openai

# 3. 运行
python AssetSpider.py
```

### AI 配置（可选）

AI 功能为可选功能，不配置也可正常使用所有扫描功能：

```json
// 编辑 config/ai_config.json
{
    "api_key": "你的API Key",
    "base_url": "https://api.deepseek.com",
    "model": "deepseek-v4-pro"
}
```

获取 API Key：
- [DeepSeek](https://platform.deepseek.com/api_keys) （推荐）
- 任意兼容 OpenAI 接口的服务

## 🛡️ 合规性设计

AssetSpider v2.1 严格区分**信息收集**与**漏洞评估**，确保工具输出符合安全测试规范：

### 模块分类

| 模块 | 分类 | 输出内容 | 不包含 |
|------|------|---------|--------|
| 子域名扫描 | ℹ️ 信息收集 | 连通性状态 + DNS解析记录 | ❌ 漏洞检测结果、风险提示 |
| 端口扫描 | ℹ️ 信息收集 | 端口号 + 开放状态 + 基础服务名 | ❌ 漏洞识别、风险评估 |
| 中间件指纹 | ⚠️ 推测性评估 | 指纹识别 + CVE匹配 + 推测性漏洞类型 | ❌ 具体利用方法、验证步骤 |
| FUZZ攻击 | ⚠️ 推测性评估 | 路径爆破 + FUZZ测试 + 推测性漏洞类型 | ❌ 具体利用方法、验证步骤 |

### 推测性结果标注

功能2和功能4的所有漏洞猜测均：
- ✅ 明确标注「[推测性结果]」前缀
- ✅ 遵循CVE/CWE标准分类
- ✅ 提供漏洞类别、可能影响范围、风险等级建议
- ✅ 附带免责声明
- ❌ 不包含具体漏洞利用方法
- ❌ 不包含验证步骤或Payload
- ❌ 不包含攻击链构造

### AI 分析约束

所有AI分析Prompt均内置严格约束：
- 仅提供推测性漏洞类型分类（CVE/CWE标准）
- 仅提供可能影响范围和风险等级建议
- 严禁输出利用方法、验证步骤、攻击链、WAF绕过等操作指导

## 🧠 AI 赋能爆破路径测试

功能4独有特色功能：当目标URL无参数/路径时，AI自动推荐可能存在漏洞的路径并FUZZ测试。

### 触发条件

- 用户输入的URL无查询参数（如 `https://example.com`）
- 或URL无具体路径（仅根域名）

### 执行流程

```
URL无参数检测
  ↓
扫描完成后询问用户
  ↓
AI分析目标特征 + 攻击类型
  ↓
AI推荐15-20个带参数的URL
  ↓
自动对推荐URL进行参数型FUZZ测试
  ↓
输出AI路径测试汇总
```

### 智能目标选择

| 攻击类型 | 测试目标 | 原因 |
|---------|---------|------|
| 参数型（SSTI/XSS/SQL/SSRF/RCE/文件上传/参数Fuzz） | 原始URL + 发现路径 + AI推荐路径 | 需要有效接口注入参数 |
| 路径型（API/敏感文件/Spring/CTF/目录爆破/JS路径） | 仅原始URL | payload本身就是路径 |

## 🎨 漏洞颜色分级系统

不同漏洞类型使用不同颜色，视觉上一目了然：

| 级别 | 颜色 | ANSI 代码 | 漏洞类型示例 |
|------|------|-----------|-------------|
| **Tier 1 严重** | 🔴 亮红加粗 | `\033[1;91m` | RCE、代码执行、命令注入、反序列化、认证绕过、权限提升 |
| **Tier 2 高危** | 🔴 亮红 | `\033[91m` | SQL 注入、未授权访问、弱口令、SSRF、源码泄露、CI/CD 攻击 |
| **Tier 3 中高危** | 🟡 亮黄 | `\033[93m` | XSS、CSRF、JWT 伪造、越权、路径遍历、XXE、暴力破解 |
| **Tier 4 中危** | 🔵 亮蓝 | `\033[94m` | WebSocket 劫持、API 滥用、协议走私、SMTP 注入 |
| **Tier 5 中低危** | 🟢 亮青 | `\033[96m` | 敏感信息泄露、数据泄露、配置信息泄露、日志泄露 |
| **Tier 6 低危** | 🟣 亮紫 | `\033[95m` | API 文档暴露、S3 配置错误、拒绝服务 |

## ❓ 常见问题解答

### Q: AI 功能是否必须？
**A:** 不是。AI 为可选功能。不配置 AI 时所有扫描功能正常运行，仅缺少智能分析环节。

### Q: 支持哪些 AI 服务？
**A:** 任何兼容 OpenAI 接口的服务均可。默认使用 DeepSeek，在 `config/ai_config.json` 中修改 `base_url` 即可切换。

### Q: 子域名扫描为什么不显示漏洞信息了？
**A:** v2.1 起子域名扫描改为**信息收集模式**，仅提供连通性测试和DNS解析记录。漏洞评估由功能2（中间件指纹）和功能4（FUZZ攻击）的**推测性结果**提供。

### Q: 端口扫描为什么不显示漏洞风险了？
**A:** v2.1 起端口扫描改为**信息收集模式**，仅提供端口号、开放状态和基础服务名（200+端口映射）。不再进行AI漏洞风险评估。

### Q: 什么是「推测性结果」？
**A:** 功能2和功能4的漏洞类型猜测均为推测性结果，遵循CVE/CWE标准分类，提供漏洞类别、影响范围和风险等级建议，但**不包含具体利用方法或验证步骤**。

### Q: 什么是 AI 赋能爆破路径测试？
**A:** 功能4中，当用户输入的URL无参数/路径时，扫描完成后会询问是否进行AI赋能爆破。AI会基于目标特征推荐15-20个可能存在漏洞的带参数URL，然后自动对这些URL进行参数型FUZZ测试。

### Q: 扫描速度慢怎么办？
**A:**
1. 调整线程数（默认 25，可提高到 50-100）
2. 切换到高危端口模式（仅扫描 100+ 高危端口）
3. 使用更小的字典文件

### Q: Windows 下运行出现乱码？
**A:** 工具已自动处理 GBK/UTF-8 编码问题。如仍有乱码，建议使用 Windows Terminal 或 PowerShell 7+。

### Q: 如何打包成 EXE？
**A:**
```bash
pip install pyinstaller
pyinstaller --onefile --console --icon=AssetSpider.ico --name=AssetSpider --hidden-import=AI AssetSpider.py
```

## 🧠 JS 逻辑深度审计

AssetSpider 的核心特色功能，AI 深度分析前端 JavaScript 代码中的安全逻辑：

### 6 大审计维度

| 维度 | 分析内容 | 风险示例 |
|------|---------|---------|
| **🔐 认证逻辑还原** | Token/JWT 生成流程、加密算法、密钥来源 | 弱签名算法、None 算法、硬编码密钥 |
| **🔌 API 端点映射** | 提取所有 API 路径、请求参数、数据格式 | 未授权访问、越权、高风险 API |
| **📊 数据流与加密** | 前端加密可逆性、密钥管理、传输安全 | 中间人攻击、反序列化、明文传输 |
| **🎯 DOM 安全审计** | innerHTML/eval/document.write 使用位置 | DOM 型 XSS、开放重定向、代码注入 |
| **💼 业务逻辑漏洞** | 支付、文件上传、审批等敏感操作 | 金额篡改、前端校验绕过、IDOR |
| **🛡️ 前端安全配置** | CORS、CSP、Cookie、Source Map 分析 | 任意源 CORS、CSP 缺失、信息泄露 |

1. 常规 AI 分析（含 JS 信息）

## ❓ 常见问题解答

### Q: AI 功能是否必须？
**A:** 不是。AI 为可选功能。不配置 AI 时所有扫描功能正常运行，仅缺少智能分析环节。

### Q: 支持哪些 AI 服务？
**A:** 任何兼容 OpenAI 接口的服务均可。默认使用 DeepSeek，在 `config/ai_config.json` 中修改 `base_url` 即可切换。

### Q: 字典库会占用大量磁盘空间吗？
**A:** 是的。完整字典库约 300MB+。如空间有限可选择性保留需要的字典文件。

### Q: 扫描速度慢怎么办？
**A:** 
1. 调整线程数（默认 25，可提高到 50-100）
2. 切换到高危端口模式（仅扫描 100+ 高危端口）
3. 使用更小的字典文件

### Q: Windows 下运行出现乱码？
**A:** 工具已自动处理 GBK/UTF-8 编码问题。如仍有乱码，建议使用 Windows Terminal 或 PowerShell 7+。

### Q: 如何打包成 EXE？
**A:**
```bash
pip install pyinstaller
pyinstaller --onefile --console --icon=AssetSpider.ico --name=AssetSpider --hidden-import=AI AssetSpider.py
```

### Q: 支持哪些漏洞类型检测？
**A:** 覆盖 OWASP Top 10 所有漏洞类型，包括但不限于：
RCE、SQL 注入、XSS、CSRF、SSRF、JWT 伪造、未授权访问、文件上传、路径遍历、反序列化、XXE、逻辑漏洞、越权、敏感信息泄露、CORS 错误、CSP 缺失等。
